# Codex Workspace Rules

## 通用工作原则
- 先理解需求、上下文和现有实现，再开始改动
- 优先做最小且可维护的修改，避免无关重构
- 做技术决策时说明理由、权衡和影响范围
- 修改代码后尽量运行相关测试；如果无法运行，要明确给出验证步骤
- 不确定时明确标注假设，不要编造事实
- 输出默认使用中文，代码、命令、配置键名保持原文

## 代码修改原则
- 保持现有代码风格和目录约定
- 未经明确需要，不要引入新的重量级依赖
- 修复问题时优先处理根因，不做表面绕过
- 涉及安全、架构、性能、文档问题时，优先使用对应专门 agent

## 输出格式偏好
- 先给结论
- 再给变更点
- 再给风险与验证方式
- 如有后续建议，单独列出，不与已完成事项混在一起

## 安全与稳定性
- 不要输出或暴露密钥、令牌、凭证
- 不要为了“快速成功”而关闭安全控制
- 涉及生产级改动时，要考虑回滚、监控和兼容性
